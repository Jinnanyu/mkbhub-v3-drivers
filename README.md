# MKBHub V3 SoC 外设驱动与板上验证

中文 | [English](README.en.md)

本仓库保存了我在北京宁矩科技有限公司实习期间完成的 SPI、PIT 定时器和 WDT 看门狗驱动，以及配套的板上测试程序、测试记录和逻辑分析仪采样文件。

- **作者：** 金南宇 / Nanyu Jin
- **实习时间：** 2025.06 - 2025.07
- **个人职责：** 独立完成 SPI、PIT、WDT 三个模块的驱动开发、测试程序编写与上板功能验证。
- **原始归档：** [Gitee 仓库](https://gitee.com/jinnanyu22/jny_mkbhub_v3_driver_git)

这是依赖配套 SoC SDK 与板卡的实习工程归档，包含外设驱动和验证材料，不是可独立编译的完整 SDK。

## 工作内容

| 模块 | 驱动内容 | 验证材料 |
| --- | --- | --- |
| SPI | 主从模式、CPOL/CPHA、数据位宽、时钟分频、FIFO 收发、状态查询、超时处理、中断配置与回调注册 | SPI 测试入口、测试报告、DSLogic 通信采样 |
| PIT | 32 位、双 16 位和四 8 位计数模式；时钟源、重装载、通道使能、中断状态处理及用户回调 | 定时中断测试入口、GPIO 翻转观测记录与采样 |
| WDT | 写保护解锁、时钟与超时参数配置、复位/中断使能、喂狗与停用 | 超时复位测试入口、测试报告与采样 |

代码中还保留了部分探索性配置。SPI 的 DMA 相关字段仅用于配置寄存器，不代表本仓库包含完整 DMA 驱动；各配置项的存在也不意味着所有组合均完成了板测。

## 阅读与验证材料

建议先查看测试文档，了解当时的测试配置和观测结果，再结合相应驱动及测试入口阅读。`DSLogic/` 中保留了 26 个 `.dsl` 文件，可用兼容的 DSView/DSLogic 软件查看原始采样。

历史上板测试由作者在实习期间完成。此次公开整理保留原始驱动与测试代码，仅补充项目说明；没有重新编译、烧录或进行硬件复测。

## 在配套工程中使用

需要准备与原工程匹配的 SoC SDK、交叉编译工具链、板卡及下载/调试环境。仓库未包含启动代码、链接脚本、Makefile/CMake 或 IDE 工程配置。

源码直接依赖但本仓库未提供的头文件包括：

```text
platform.h
interrupt.h
ndslib.h
uwb_drivers.h
mkb03_ct_func.h
atcpit100.h
atcwdt200.h
```

这些依赖及相关平台文件需要提供寄存器定义和位域宏、外设基址、中断号与处理入口、GPIO 及延时等支持。

1. 在匹配 SDK 的示例工程中集成相应驱动文件，并核对板卡的时钟、引脚复用和外设连接。
2. 一次只选择一个 `main()`。例如测试 PIT 时，将 `test_pit_main.txt` 作为 C 源文件加入工程，并排除其他测试入口及原 `main.c`。
3. 当前 `*_driver_user.h` 含非静态函数定义，宜仅由一个翻译单元包含，避免重复定义。
4. 按实际 SPI 实例、PIT 通道、时钟源和 WDT 复位行为调整配置，再进行编译、下载和板测。

代码中的 `USE_72M` 等宏只表示测试配置，不能替代平台的时钟初始化。由于 SDK 与工具链未随仓库提供，这里不提供无法独立验证的通用构建命令。

## 原始调试代码的使用边界

以下问题仍保留在归档版本中，重新使用前应结合配套工程检查和修正：

- `main.c` 的测试缓冲区分配大小与 `uint32_t` 写入数量不一致，另有 `1 << 32` 的移位问题，不应直接作为可运行示例使用。
- 部分 SPI 中断禁用/清除逻辑固定使用 `INT_NO_SPI2`，切换 SPI 实例时需要同步核对中断映射。
- PIT 与 WDT 公共头重用了 `err_t`、`err_success` 等名称，混合包含时需要处理命名冲突。
- WDT 测试入口中的 PIT 中断处理器注册处于注释状态，不能将其视为已启用的定时中断自动喂狗配置。

本仓库用于记录外设驱动开发与板上调试经历。移植到其他硬件时，应重新核对寄存器、时钟、中断及复位逻辑，并完成对应的功能验证。
